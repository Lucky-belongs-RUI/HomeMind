## 1. 项目概述

### 1.1 项目背景与目标

随着大语言模型（LLM）与智能体（Agent）技术的成熟，传统智能家居平台正从"规则触发"向"自然语言驱动 + 个性化推理"演进。本项目旨在构建一个**智能家居大模型体验平台**，通过多智能体协同、检索增强生成（RAG）、知识图谱小模型节点（虚拟实现）与真实设备状态模拟，为用户提供拟人化、可交互、可个性化的智能家居管理体验。

平台以前后端分离架构为基础，以 MySQL 作为设备状态唯一数据源，通过 WebSocket 实现前端实时同步，结合虚拟形象与语音交互，打造完整的智能家庭交互闭环。LLM 调用采用统一适配层封装，可灵活切换 Qwen（通义千问）、DeepSeek、质谱 GLM 等国内主流模型。

### 1.2 核心能力

1. **设备与房间可视化管理**：支持房间、设备的全生命周期增删改查，设备状态持久化存储于 MySQL，前端以卡片形式可视化展示与控制。每个设备拥有差异化状态结构（如空调的温度/模式/风量、扫地机器人的电量/位置/清扫模式）。
2. **AI 助理自然语言控制**：基于 LangChain + LangGraph 构建 Agent，用户通过文字/语音下达指令，Agent 通过 Function Calling（工具调用）修改数据库中的设备状态，并通过 WebSocket 推送到前端实时更新。Agent 具备多轮对话上下文记忆与工具调用循环能力。
3. **虚拟形象交互**：提供卡通虚拟形象，支持语音播报、表情/动作切换（idle/speaking/thinking/happy/sad 等），根据回复情感动态切换形象状态。
4. **私有知识库 RAG**：用户可上传 PDF/Word 格式的私人数据（如生活习惯、偏好说明），系统解析后构建个人向量库，AI 可基于私有知识进行个性化回答。
5. **知识图谱小模型节点（虚拟实现）**：作为 Agent 状态图中的一个节点存在，当前阶段返回虚拟信息（mock 数据），不进行真实图谱构建。节点接口已预留，后期可替换为真实知识图谱引擎。详见第 4.6 节。
6. **对话历史与偏好学习**：完整保存对话记录，定期分析用户行为并生成偏好画像（常用温度、作息、兴趣话题），用于 Agent 个性化回复。
7. **家庭化数据隔离**：以家庭为数据隔离最高单位，所有数据（房间、设备、场景、对话、文件、操作日志）绑定于家庭 id。住户和访客不单独绑定数据，与房主及其他成员共享同一家庭下的所有设备状况等数据。
8. **登录注册与子账户体系**：房主可注册家庭（注册时创建家庭并成为房主），房主可创建直接子账户（住户、访客），子账户可通过房主注册的用户名密码登录。身份权限分级：房主可创建用户、管理家庭所有数据；住户可控制设备但不能创建用户；访客仅可查看。所有数据绑定于家庭 id，住户和访客共享房主家庭下的数据。
9. **设备模拟引擎**：时间驱动的状态模拟，如扫地机器人电量随时间下降、位置按路径移动，定时更新数据库并推送前端，使平台具备"活态"演示能力。
10. **场景联动**：支持"回家模式""睡眠模式"等一键批量设备操作，Agent 可通过自然语言触发场景。

### 1.3 核心设计原则

- **家庭隔离优先**：所有业务数据（房间、设备、场景、对话、文件、操作日志）以家庭为单位隔离，所有查询必须带 family_id 过滤，禁止跨家庭数据访问。住户和访客不单独绑定数据，所有数据绑定于家庭 id，与房主共享。
- **状态唯一源**：MySQL 为设备状态的唯一可信数据源，所有状态变更必须经过数据库，再通过消息机制同步前端。禁止前端本地状态作为最终判定依据。
- **前后端分离**：前端负责交互与渲染，后端负责业务逻辑、AI 能力与数据持久化，通过 REST API + WebSocket 通信。
- **JWT 认证**：用户登录后获取 JWT token，前端请求携带 Authorization 头，后端解析 token 获取用户身份与 family_id，实现认证与数据隔离。
- **高内聚低耦合**：Agent 逻辑、设备控制、RAG、语音处理、LLM 适配层、家庭管理、认证服务模块化拆分，通过接口交互，便于独立迭代。
- **LLM 适配层抽象**：所有 LLM 调用必须经过统一适配层 `LLMClient`，业务代码不直接依赖具体模型 SDK，便于切换模型与多模型路由。
- **工具调用优先于 SQL 生成**：Agent 控制设备采用 Function Calling（预定义工具），而非让 LLM 生成 SQL 代码执行。原因详见第 4.5 节。
- **可观测性**：设备状态、对话过程、工具调用全程可追溯，便于调试与问题排查。

### 1.4 术语表

| 术语 | 含义 |
|------|------|
| Agent | 基于 LangGraph 构建的智能体，接收用户指令并自主调用工具完成任务 |
| Function Calling | LLM 根据预定义工具签名，返回结构化工具调用请求的机制 |
| RAG | 检索增强生成，从向量库检索相关文档片段注入 LLM 上下文 |
| KG 节点 | 知识图谱小模型节点，Agent 状态图中的一个节点，当前为虚拟实现 |
| 设备模拟引擎 | 定时任务驱动的设备状态自动演化模块 |
| 状态唯一源 | MySQL 数据库，所有设备状态的唯一可信来源 |

### 2.4 数据流向（核心场景）

**场景：用户对 AI 助理说"将卧室空调调整到 27 度"**

```text
用户语音/文字输入
    │
    ▼
前端 AI助理页 (录音 → Whisper STT / 直接文字)
    │
    ▼ POST /api/agent/chat
后端 Agent 服务
    │
    ▼ LangGraph 状态图
    │
    ├─① RAG 节点：检索用户私有知识库（如有相关偏好）→ 注入上下文
    │
    ├─② KG 节点（虚拟）：返回虚拟的房间-设备关系信息 → 注入上下文
    │
    ├─③ Agent 节点：调用 LLMClient.chat_with_tools()
    │     │
    │     ▼ LLM 分析意图，返回工具调用
    │     │  tool_name: "set_device_state"
    │     │  args: {
    │     │    room_name: "卧室",
    │     │    device_type: "air_conditioner",
    │     │    attributes: {"temperature": 27, "power": "on"}
    │     │  }
    │     │
    │     ▼
    ├─④ 工具执行节点：执行 set_device_state
    │     │
    │     ▼ 查询数据库：找到卧室的空调设备
    │     │  SELECT * FROM devices
    │     │  WHERE room_id = (SELECT id FROM rooms WHERE name='卧室')
    │     │    AND type = 'air_conditioner'
    │     │
    │     ▼ 权限校验：当前角色是否可操作该设备
    │     │
    │     ▼ 更新数据库：
    │     │  UPDATE devices
    │     │  SET status = JSON_SET(status, '$.temperature', 27, '$.power', 'on')
    │     │  WHERE id = <device_id>
    │     │
    │     ▼ 记录操作日志
    │     │
    │     ▼ 通过 WebSocket 推送状态变更
    │     │
    │     ▼ 返回工具执行结果给 Agent
    │
    ├─⑤ Agent 节点（二次调用 LLM）：根据工具结果生成自然语言回复
    │     "已将卧室空调调整到 27 度并开启"
    │
    ▼
WebSocket 推送 → 前端设备卡片实时更新温度显示
WebSocket 推送 → 前端 AI 助理显示回复 + 虚拟形象切换为 speaking
TTS 合成语音 → 前端播放语音回复
```

**完整链路验证点**：
- 数据库 `devices` 表中卧室空调的 `status` 字段 `temperature` 值变为 27 ✓
- 前端卧室空调卡片温度显示实时变为 27 ✓
- AI 助理返回确认消息 ✓
- 虚拟形象切换为 speaking 状态 ✓

## 3. 数据库设计（MySQL）

### 3.1 设计原则

- **家庭隔离**：所有业务数据（房间、设备、场景、对话、文件、操作日志）以家庭为单位隔离，每个家庭拥有独立的房间和设备集合，互不干扰。这是本平台作为"智能家居模拟体验平台"的核心设计——每个家庭模拟一个独立的智能家居环境，不同家庭的房间和设备完全不同。
- **房主绑定**：一条家庭数据必须有一个房主用户（owner），房主创建家庭时自动绑定。房主可创建住户和访客，创建的用户自动绑定到同一家庭，共享家庭下的房间、设备等数据。
- **状态唯一源**：所有设备状态以 `devices.status` 字段（JSON 类型）为唯一可信来源，前端展示与 Agent 控制均读写此字段。
- **JSON 存储差异化状态**：不同设备类型状态结构不同（空调有温度、扫地机器人有电量），采用 JSON 字段灵活存储，避免表结构频繁变更。
- **软删除**：家庭、房间与设备采用 `is_active` 软删除标记，保留历史数据用于对话追溯。
- **操作日志**：所有设备状态变更记录到 `device_operation_logs` 表，便于审计与回滚。
- **索引优化**：高频查询字段（family_id、room_id、type、user_id）建立索引，所有业务表均以 family_id 为第一索引字段，确保按家庭查询的性能。

### 3.2 ER 关系概览

```text
families (家庭) ★核心表
  │ 1
  │          （owner_user_id 指向房主用户，唯一约束）
  │
  │ 1
  │
users (用户，含 owner/resident/guest 三种角色)
  │ N          （所有用户通过 family_id 关联到家庭）
  │
  │  房主创建住户/访客 → 新用户 family_id = 房主的 family_id
  │  住户和访客自动共享家庭下所有房间、设备、场景

families 1───N rooms (房间，通过 family_id 隔离)
families 1───N devices (设备，通过 family_id 隔离)
families 1───N scenes (场景，通过 family_id 隔离)
families 1───N conversations (对话历史)
families 1───N uploaded_files (上传文件)
families 1───N device_operation_logs (操作日志)

rooms 1───N devices (设备属于房间)
devices 1───N device_operation_logs
users 1───1 user_preferences (偏好画像)
```

> **关键变化**：
> - **新增 `families` 表**：家庭是数据隔离的最高单位，每个家庭模拟一个独立的智能家居环境。
> - **删除 `user_room_relations` 表**：住户和访客通过 `family_id` 自动共享家庭下所有房间，权限通过角色（role）判断，无需显式关联。
> - **所有业务表新增 `family_id`**：rooms、devices、scenes、conversations、uploaded_files、device_operation_logs 均以 family_id 关联到家庭。
> - 知识图谱相关表当前阶段不创建，KG 节点返回虚拟信息。

### 3.3 表结构详细定义

#### 3.3.1 families（家庭表）★新增核心表

```sql
CREATE TABLE families (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  name            VARCHAR(64)  NOT NULL COMMENT '家庭名称，如"张三的家"',
  owner_user_id   BIGINT       NOT NULL COMMENT '房主用户ID',
  description     TEXT         COMMENT '家庭描述',
  is_active       TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '是否启用（软删除）',
  created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_owner (owner_user_id) COMMENT '一个用户只能是一个家庭的房主',
  INDEX idx_active (is_active)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='家庭表';
```

> **设计说明**：
> - `owner_user_id` 唯一约束：确保一个用户只能是一个家庭的房主，一对一关系。
> - 创建家庭流程：① 创建用户（role=owner，family_id 暂为 0）→ ② 创建家庭（owner_user_id 指向该用户）→ ③ 更新用户的 family_id 指向新家庭。
> - 家庭是数据隔离的最高单位，所有房间、设备、场景、对话、文件、操作日志都通过 family_id 关联到家庭。
> - 作为模拟体验平台，可创建多个家庭模拟不同环境（如"张三的家""赵六的家"），每个家庭拥有完全不同的房间和设备配置。

#### 3.3.2 users（用户表）★修改

```sql
CREATE TABLE users (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  username    VARCHAR(64)  NOT NULL UNIQUE COMMENT '用户名，登录用',
  password    VARCHAR(255) NOT NULL COMMENT '密码哈希（bcrypt），登录验证用',
  nickname    VARCHAR(64)  NOT NULL COMMENT '昵称，前端展示',
  role        ENUM('owner','resident','guest') NOT NULL DEFAULT 'guest'
              COMMENT '角色：房主/住户/访客',
  family_id   BIGINT       NOT NULL COMMENT '所属家庭ID，所有用户必须关联一个家庭',
  avatar_url  VARCHAR(255) COMMENT '头像URL',
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_family (family_id),
  INDEX idx_role (role),
  FOREIGN KEY (family_id) REFERENCES families(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

> **设计说明**：
> - `password` 字段存储 bcrypt 哈希值，登录时用 bcrypt 校验，**禁止明文存储密码**。
> - `family_id` 必填：所有用户必须属于一个家庭。房主注册家庭后，自己的 family_id 指向该家庭；房主创建的住户/访客，family_id 自动继承房主的 family_id，实现数据共享。
> - **角色权限**：
>   - **房主（owner）**：注册家庭时产生，管理家庭、创建住户/访客子账户、管理房间/设备/场景，可触发所有操作。
>   - **住户（resident）**：由房主创建，共享家庭数据，可控制设备，**不可创建用户**、不可管理房间。
>   - **访客（guest）**：由房主创建，共享家庭数据，仅可查看，不可修改任何设备。
> - **创建用户规则**：只有房主可创建住户和访客子账户；创建时 family_id 自动继承房主的 family_id；不可创建 owner 角色用户（owner 只能通过注册新家庭产生）。
> - **登录规则**：房主、住户、访客均可通过用户名 + 密码登录。登录后获取 JWT token，后续请求携带 Authorization 头。

### 3.5 索引与性能优化总结

| 查询场景 | 涉及表 | 索引 |
|----------|--------|------|
| 查询某家庭所有设备 | devices | idx_family |
| 查询某家庭某房间设备 | devices | idx_family_room |
| 查询某家庭某类型设备 | devices | idx_family_type |
| 查询某家庭所有房间 | rooms | idx_family_active |
| 查询某家庭对话历史 | conversations | idx_family_user_session |
| 查询某家庭设备操作日志 | device_operation_logs | idx_family_device, idx_family_created |
| 查询某家庭所有场景 | scenes | idx_family_active |
| 查询家庭所有用户 | users | idx_family |
| 查询用户偏好 | user_preferences | 主键 user_id |

> **性能要点**：所有业务查询均以 family_id 作为第一过滤条件，确保数据隔离的同时利用复合索引高效查询。禁止跨家庭查询（除非管理后台）。

### 4.4 认证服务（auth_service.py）★新增

#### 4.4.1 设计说明

认证服务负责用户登录、注册、JWT token 生成与校验。核心流程：

1. **房主注册家庭**：房主提交家庭名称 + 用户名 + 密码 → 创建家庭 + 创建房主用户（role=owner）+ 绑定 family_id → 返回 JWT token。
2. **房主创建子账户**：房主登录后，提交子账户用户名 + 密码 + 角色（resident/guest）→ 创建用户并绑定到房主的 family_id → 子账户可用用户名密码登录。
3. **用户登录**：用户名 + 密码 → bcrypt 校验 → 生成 JWT（含 user_id、role、family_id）→ 返回 token + 用户信息 + 家庭信息。
4. **请求认证**：前端请求携带 `Authorization: Bearer <token>`，后端中间件解析 token 获取用户身份，注入请求上下文。

#### 4.4.2 认证服务实现

```python
import jwt
import bcrypt
from datetime import datetime, timedelta
from typing import Optional
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from app.models.user import User
from app.models.family import Family
from app.database import get_db_session
from app.config import settings

class AuthService:
    """认证服务：登录、注册、JWT 管理"""
    
    @staticmethod
    def hash_password(password: str) -> str:
        """密码哈希（bcrypt）"""
        return bcrypt.hashpw(password.encode(), bcrypt.gensalt()).decode()
    
    @staticmethod
    def verify_password(password: str, hashed: str) -> bool:
        """校验密码"""
        return bcrypt.checkpw(password.encode(), hashed.encode())
    
    @staticmethod
    def create_jwt_token(user: User) -> str:
        """生成 JWT token，含 user_id、role、family_id"""
        payload = {
            "user_id": user.id,
            "username": user.username,
            "role": user.role,
            "family_id": user.family_id,
            "exp": datetime.utcnow() + timedelta(hours=settings.jwt_expire_hours),
        }
        return jwt.encode(payload, settings.jwt_secret, algorithm=settings.jwt_algorithm)
    
    @staticmethod
    def decode_jwt_token(token: str) -> dict:
        """解析 JWT token，返回 payload"""
        try:
            return jwt.decode(token, settings.jwt_secret, algorithms=[settings.jwt_algorithm])
        except jwt.ExpiredSignatureError:
            raise ValueError("Token 已过期，请重新登录")
        except jwt.InvalidTokenError:
            raise ValueError("无效的 Token")
    
    # ============ 注册家庭（房主）============
    
    async def register_family(
        self, family_name: str, username: str, password: str,
        nickname: str, description: str = None
    ) -> dict:
        """房主注册家庭：创建家庭 + 创建房主用户 + 绑定
        
        流程：
        1. 校验用户名唯一
        2. 创建房主用户（role=owner, family_id=0 临时）
        3. 创建家庭（owner_user_id 指向房主）
        4. 更新房主 family_id 指向新家庭
        5. 生成 JWT token 返回
        """
        async with get_db_session() as db:
            # 1. 校验用户名唯一
            existing = await db.execute(select(User).where(User.username == username))
            if existing.scalar_one_or_none():
                raise ValueError("用户名已存在")
            
            # 2. 创建房主用户
            owner = User(
                username=username,
                password=self.hash_password(password),
                nickname=nickname,
                role="owner",
                family_id=0,  # 临时，创建家庭后更新
            )
            db.add(owner)
            await db.flush()
            
            # 3. 创建家庭
            family = Family(
                name=family_name,
                owner_user_id=owner.id,
                description=description,
            )
            db.add(family)
            await db.flush()
            
            # 4. 更新房主 family_id
            owner.family_id = family.id
            await db.commit()
            
            # 5. 生成 token
            token = self.create_jwt_token(owner)
            return {
                "token": token,
                "user": {
                    "id": owner.id,
                    "username": owner.username,
                    "nickname": owner.nickname,
                    "role": owner.role,
                    "family_id": family.id,
                },
                "family": {
                    "id": family.id,
                    "name": family.name,
                    "description": family.description,
                },
            }
    
    # ============ 房主创建子账户 ============
    
    async def create_sub_account(
        self, username: str, password: str, nickname: str,
        role: str, creator_user_id: int
    ) -> User:
        """房主创建子账户（住户/访客）
        
        校验：
        - 创建者必须是房主（owner）
        - role 只能是 resident 或 guest（不可创建 owner）
        - 子账户 family_id 自动继承房主的 family_id
        """
        if role not in ("resident", "guest"):
            raise ValueError("子账户角色只能是 resident 或 guest")
        
        async with get_db_session() as db:
            # 校验创建者权限
            creator = await db.get(User, creator_user_id)
            if not creator or creator.role != "owner":
                raise PermissionError("只有房主可以创建子账户")
            
            # 校验用户名唯一
            existing = await db.execute(select(User).where(User.username == username))
            if existing.scalar_one_or_none():
                raise ValueError("用户名已存在")
            
            # 创建子账户，family_id 继承房主的
            sub_user = User(
                username=username,
                password=self.hash_password(password),
                nickname=nickname,
                role=role,
                family_id=creator.family_id,  # 继承房主的家庭
            )
            db.add(sub_user)
            await db.commit()
            await db.refresh(sub_user)
            return sub_user
    
    # ============ 用户登录 ============
    
    async def login(self, username: str, password: str) -> dict:
        """用户登录（房主/住户/访客均可）
        
        流程：
        1. 根据用户名查询用户
        2. bcrypt 校验密码
        3. 生成 JWT token
        4. 返回 token + 用户信息 + 家庭信息
        """
        async with get_db_session() as db:
            user = await db.execute(select(User).where(User.username == username))
            user = user.scalar_one_or_none()
            if not user:
                raise ValueError("用户名或密码错误")
            
            if not self.verify_password(password, user.password):
                raise ValueError("用户名或密码错误")
            
            # 查询家庭信息
            family = await db.get(Family, user.family_id)
            
            token = self.create_jwt_token(user)
            return {
                "token": token,
                "user": {
                    "id": user.id,
                    "username": user.username,
                    "nickname": user.nickname,
                    "role": user.role,
                    "family_id": user.family_id,
                },
                "family": {
                    "id": family.id,
                    "name": family.name,
                    "description": family.description,
                } if family else None,
            }

auth_service = AuthService()
```

```python
from fastapi import Depends, HTTPException, Header
from typing import Optional
from app.services.auth_service import auth_service

async def get_current_user(authorization: str = Header(...)) -> dict:
    """FastAPI 依赖：从 Authorization 头解析当前用户身份
    
    所有需要认证的接口使用：current_user = Depends(get_current_user)
    """
    if not authorization.startswith("Bearer "):
        raise HTTPException(401, "认证失败：缺少 Bearer token")
    
    token = authorization[7:]
    payload = auth_service.decode_jwt_token(token)
    
    return {
        "user_id": payload["user_id"],
        "username": payload["username"],
        "role": payload["role"],
        "family_id": payload["family_id"],
    }

async def require_owner(current_user: dict = Depends(get_current_user)) -> dict:
    """FastAPI 依赖：要求房主权限"""
    if current_user["role"] != "owner":
        raise HTTPException(403, "需要房主权限")
    return current_user

async def require_owner_or_resident(current_user: dict = Depends(get_current_user)) -> dict:
    """FastAPI 依赖：要求房主或住户权限（可控制设备）"""
    if current_user["role"] not in ("owner", "resident"):
        raise HTTPException(403, "需要房主或住户权限")
    return current_user
```

### 4.5 LLM 适配层设计 ★核心新增

#### 4.4.1 设计目标

LLM 适配层是本项目关键设计，所有 LLM 调用必须经过此层，业务代码不直接依赖具体模型 SDK。实现以下目标：

1. **统一接口**：业务代码调用 `LLMClient.chat()` / `LLMClient.chat_with_tools()`，无需关心底层是 Qwen、DeepSeek 还是质谱。
2. **灵活切换**：通过配置项 `LLM_PROVIDER` 一键切换模型，无需改代码。
3. **统一消息格式**：不同模型的消息格式略有差异，适配层内部转换。
4. **统一工具调用格式**：不同模型的 Function Calling 格式不同，适配层统一为 OpenAI 风格的 tool_calls。
5. **流式输出支持**：统一流式接口，便于前端打字机效果。
6. **错误处理与重试**：统一异常处理与重试机制。

#### 4.4.2 统一消息格式（message.py）

```python
from typing import List, Optional, Literal, Dict, Any
from pydantic import BaseModel

class ToolDefinition(BaseModel):
    """工具定义，传给 LLM 让其知道可调用哪些工具"""
    name: str
    description: str
    parameters: Dict[str, Any]  # JSON Schema 格式

class ToolCall(BaseModel):
    """LLM 返回的工具调用请求"""
    id: str                     # 工具调用 ID，用于关联工具执行结果
    name: str                   # 工具名称
    arguments: Dict[str, Any]   # 工具参数（已解析为 dict）

class Message(BaseModel):
    """统一消息格式"""
    role: Literal["system", "user", "assistant", "tool"]
    content: Optional[str] = None
    tool_calls: Optional[List[ToolCall]] = None    # assistant 调用工具时
    tool_call_id: Optional[str] = None             # role=tool 时关联的调用 ID
    name: Optional[str] = None                      # role=tool 时工具名称

class LLMResponse(BaseModel):
    """LLM 统一响应"""
    content: Optional[str] = None               # 文本回复
    tool_calls: Optional[List[ToolCall]] = None # 工具调用请求
    finish_reason: str = "stop"                 # stop / tool_calls / length
    usage: Dict[str, int] = {}                   # token 用量
```

#### 4.4.3 抽象基类（base.py）

```python
from abc import ABC, abstractmethod
from typing import List, Optional, AsyncIterator
from .message import Message, ToolDefinition, LLMResponse

class BaseLLMClient(ABC):
    """LLM 适配层抽象基类，所有模型适配器必须实现此接口"""
    
    @abstractmethod
    async def chat(
        self,
        messages: List[Message],
        system: Optional[str] = None,
        temperature: float = 0.7,
        max_tokens: int = 2048,
    ) -> LLMResponse:
        """普通对话，不带工具调用"""
        pass
    
    @abstractmethod
    async def chat_with_tools(
        self,
        messages: List[Message],
        tools: List[ToolDefinition],
        system: Optional[str] = None,
        temperature: float = 0.7,
        max_tokens: int = 2048,
    ) -> LLMResponse:
        """带工具调用的对话，LLM 可能返回 tool_calls"""
        pass
    
    @abstractmethod
    async def stream_chat(
        self,
        messages: List[Message],
        system: Optional[str] = None,
    ) -> AsyncIterator[str]:
        """流式输出，逐 token 返回"""
        pass
    
    @abstractmethod
    async def embed(self, texts: List[str]) -> List[List[float]]:
        """文本向量化，用于 RAG"""
        pass
```

```python
        system: Optional[str] = None,
        temperature: float = 0.7,
        max_tokens: int = 2048,
    ) -> LLMResponse:
        openai_messages = self._to_openai_messages(messages, system)
        resp = await self.client.chat.completions.create(
            model=self.model,
            messages=openai_messages,
            temperature=temperature,
            max_tokens=max_tokens,
        )
        return LLMResponse(
            content=resp.choices[0].message.content,
            finish_reason=resp.choices[0].finish_reason,
            usage={"prompt_tokens": resp.usage.prompt_tokens,
                   "completion_tokens": resp.usage.completion_tokens},
        )
    
    async def chat_with_tools(
        self,
        messages: List[Message],
        tools: List[ToolDefinition],
        system: Optional[str] = None,
        temperature: float = 0.7,
        max_tokens: int = 2048,
    ) -> LLMResponse:
        openai_messages = self._to_openai_messages(messages, system)
        openai_tools = [{"type": "function", "function": {
            "name": t.name,
            "description": t.description,
            "parameters": t.parameters,
        }} for t in tools]
        
        resp = await self.client.chat.completions.create(
            model=self.model,
            messages=openai_messages,
            tools=openai_tools,
            tool_choice="auto",
            temperature=temperature,
            max_tokens=max_tokens,
        )
        
        choice = resp.choices[0]
        tool_calls = None
        if choice.message.tool_calls:
            import json
            tool_calls = [
                ToolCall(
                    id=tc.id,
                    name=tc.function.name,
                    arguments=json.loads(tc.function.arguments),
                )
                for tc in choice.message.tool_calls
            ]
        
        return LLMResponse(
            content=choice.message.content,
            tool_calls=tool_calls,
            finish_reason=choice.finish_reason,
            usage={"prompt_tokens": resp.usage.prompt_tokens,
                   "completion_tokens": resp.usage.completion_tokens},
        )
    
    async def stream_chat(
        self,
        messages: List[Message],
        system: Optional[str] = None,
    ) -> AsyncIterator[str]:
        openai_messages = self._to_openai_messages(messages, system)
        stream = await self.client.chat.completions.create(
            model=self.model,
            messages=openai_messages,
            stream=True,
        )
        async for chunk in stream:
            if chunk.choices[0].delta.content:
                yield chunk.choices[0].delta.content
    
    async def embed(self, texts: List[str]) -> List[List[float]]:
        resp = await self.client.embeddings.create(
            model="text-embedding-v2",
            input=texts,
        )
        return [item.embedding for item in resp.data]
    
    def _to_openai_messages(self, messages: List[Message], system: Optional[str]):
        result = []
        if system:
            result.append({"role": "system", "content": system})
        for m in messages:
            if m.role == "tool":
                result.append({
                    "role": "tool",
                    "tool_call_id": m.tool_call_id,
                    "content": m.content,
                })
            elif m.role == "assistant" and m.tool_calls:
                result.append({
                    "role": "assistant",
                    "content": m.content,
                    "tool_calls": [
                        {"id": tc.id, "type": "function",
                         "function": {"name": tc.name, "arguments": __import__("json").dumps(tc.arguments)}}
                        for tc in m.tool_calls
                    ],
                })
            else:
                result.append({"role": m.role, "content": m.content})
        return result
```

### 4.5 Agent 设计（LangGraph）★核心

#### 4.5.1 为什么用 Function Calling 而非"LLM 生成 SQL 执行"

用户提出过一种方案："让 LLM 根据数据库表结构生成 MySQL 代码，后端提取执行"。本项目**不采用此方案**，改用 Function Calling（工具调用），原因如下：

| 对比维度 | LLM 生成 SQL 执行（不推荐） | Function Calling 工具调用（推荐，本项目采用） |
|----------|------------------------------|----------------------------------------------|
| **安全性** | 极高风险：LLM 可能生成 DROP/DELETE/UPDATE 误操作，导致数据丢失 | 安全：LLM 只能调用预定义工具，工具内部实现安全校验 |
| **SQL 注入** | LLM 生成 SQL 拼接用户输入，注入风险高 | 无 SQL 注入：工具参数走 ORM 参数化查询 |
| **权限控制** | 难以在 SQL 层面做角色权限校验 | 工具实现中可加入角色校验，拒绝越权操作 |
| **可审计** | 难以追溯哪条 SQL 由哪条指令触发 | 工具调用有明确签名，记录到 device_operation_logs |
| **可调试** | LLM 生成 SQL 出错难定位 | 工具签名固定，出错易排查 |
| **稳定性** | LLM 可能生成语法错误的 SQL | 工具实现固定，行为可预测 |
| **多模型兼容** | 不同模型 SQL 生成能力差异大 | Function Calling 是行业标准，主流模型均支持 |
| **实现复杂度** | 需要解析 LLM 输出提取 SQL，容错复杂 | LangGraph 原生支持工具调用循环 |

**结论**：Function Calling 是 LangChain/LangGraph 的标准范式，安全性、可控性、可审计性远优于让 LLM 生成 SQL。本项目所有设备控制均通过预定义工具实现。

> **补充**：对于复杂查询场景（如"统计每个房间设备数量"），可后续扩展 Text-to-SQL 工具，但**仅限 SELECT 查询**，通过白名单 + 只读数据库账号双重限制。当前阶段不实现。

```python
from typing import List, Optional, Dict, Any, Annotated
from typing_extensions import TypedDict

    # 最终回复
```

#### 4.5.3 LangGraph 状态图定义（graph.py）

```python
from langgraph.graph import StateGraph, END
from .state import AgentState
from .nodes.rag_node import rag_node
from .nodes.kg_node import kg_node
from .nodes.agent_node import agent_node
from .nodes.tool_node import tool_node
from .tools.device_tools import get_all_tools

MAX_ITERATIONS = 5  # 最大工具调用循环次数，防止死循环

def should_continue(state: AgentState) -> str:
    """路由函数：判断 Agent 节点后是继续调用工具还是结束"""
    if state.get("iteration", 0) >= MAX_ITERATIONS:
        return END
    last_message = state["messages"][-1]
    # 如果 LLM 返回了 tool_calls，则路由到工具节点
    if last_message.get("tool_calls"):
        return "tools"
    return END

def build_agent_graph():
    """构建 Agent 状态图"""
    workflow = StateGraph(AgentState)
    
    # 添加节点
    workflow.add_node("rag", rag_node)        # RAG 检索节点
    workflow.add_node("kg", kg_node)           # 知识图谱节点（虚拟）
    workflow.add_node("agent", agent_node)    # LLM 调用节点
    workflow.add_node("tools", tool_node)     # 工具执行节点
    
    # 设置入口
    workflow.set_entry_point("rag")
    
    # 添加边
    workflow.add_edge("rag", "kg")             # RAG → KG
    workflow.add_edge("kg", "agent")           # KG → Agent
    workflow.add_conditional_edges(
        "agent",
        should_continue,                      # 根据是否有 tool_calls 路由
        {
            "tools": "tools",
            END: END,
        }
    )
    workflow.add_edge("tools", "agent")       # 工具执行后回到 Agent（循环）
    
    return workflow.compile()

# 全局 Agent 实例
agent_app = build_agent_graph()
```

**状态图流转示意**：

```text
START → rag → kg → agent ──(有 tool_calls)──→ tools → agent ──(无 tool_calls)──→ END
                         └──(无 tool_calls)──→ END
```

```python

from app.llm.message import Message, ToolDefinition

from app.services.conversation_service import save_conversation

SYSTEM_PROMPT = """你是一个智能家居助理，可以帮助用户控制家中设备。

你可以调用以下工具来完成任务：
- set_device_state：设置设备状态（如空调温度、灯光亮度）

{rag_context}

    system = SYSTEM_PROMPT.format(
        kg_context=state.get("kg_context", ""),
        rag_context=state.get("rag_context", ""),
    )

    )

        role="assistant",
        content=response.content,

    )

        user_id=state["user_id"],
        session_id=state["session_id"],
        role="assistant",
        content=response.content or "",
        tool_calls=[tc.dict() for tc in response.tool_calls] if response.tool_calls else None,
    )
    
    # 增加迭代计数
    state["iteration"] = state.get("iteration", 0) + 1
    
    # 如果没有工具调用，说明 LLM 给出了最终回复
    if not response.tool_calls:
        state["final_response"] = response.content
    
    return state
```

```python

async def _tool_set_device_state(
    arguments: Dict[str, Any], user_id: int, user_role: str, family_id: int
) -> Dict[str, Any]:
    """★核心工具：设置设备状态，完整链路（含家庭隔离）"""
    room_name = arguments["room_name"]
    device_type = arguments["device_type"]
    attributes = arguments["attributes"]
    
    # 1. 查找房间（必须在当前家庭内查找）
    room = await get_room_by_name(room_name, family_id)
    if not room:
        return {"success": False, "error": f"家庭中未找到房间: {room_name}"}
    
    # 2. 权限校验：基于角色判断（住户和访客共享家庭数据，但访客不可操作）
    has_permission = _check_role_permission(user_role)
    if not has_permission:
        return {"success": False, "error": f"访客无权操作设备: {room_name}"}
    
    # 3. 查找设备（在当前家庭内查找）
    device = await get_device_by_room_and_type(room.id, device_type, family_id)
    if not device:
        return {"success": False, "error": f"房间 {room_name} 中未找到 {device_type} 类型设备"}
    
    # 4. 业务规则校验：空调调温度时自动开启
    if device_type == "air_conditioner" and "temperature" in attributes:
        attributes["power"] = "on"
    
    # 5. 参数范围校验
    validation_error = _validate_attributes(device_type, attributes)
    if validation_error:
        return {"success": False, "error": validation_error}
    
    # 6. 更新数据库（核心步骤）
    updated_device = await update_device_status(
        device_id=device.id,
        attributes=attributes,
        user_id=user_id,
        source="agent",  # 标记为 Agent 操作
    )
    
    # 7. 通过 WebSocket 推送状态变更到前端
    await broadcast_device_update({
        "type": "device_status_update",
        "device_id": device.id,
        "room_id": room.id,
        "device_type": device_type,
        "status": updated_device.status,
    })
    
    return {
        "success": True,
        "device_id": device.id,
        "device_name": device.name,
        "room_name": room_name,
        "updated_attributes": attributes,
        "current_status": updated_device.status,
        "message": f"已成功更新 {room_name} 的 {device.name} 状态"
    }

# ============ 辅助函数 ============

def _check_role_permission(user_role: str) -> bool:
    """基于角色的权限校验：房主和住户可操作设备，访客不可操作。
    
    家庭化设计后，权限基于角色判断，不再需要检查用户-房间关联表。
    住户和访客通过 family_id 自动共享家庭下所有房间和设备。
    """
    return user_role in ("owner", "resident")

def _validate_attributes(device_type: str, attributes: Dict) -> Optional[str]:
    """参数范围校验"""
    if device_type == "air_conditioner":
        if "temperature" in attributes:
            temp = attributes["temperature"]
            if not (16 <= temp <= 30):
                return f"空调温度需在 16-30 之间，当前: {temp}"
        if "mode" in attributes:
            if attributes["mode"] not in ["cool", "heat", "fan", "dry", "auto"]:
                return f"空调模式无效: {attributes['mode']}"
    elif device_type == "light":
        if "brightness" in attributes:
            if not (0 <= attributes["brightness"] <= 100):
                return "灯光亮度需在 0-100 之间"
    elif device_type == "curtain":
        if "position" in attributes:
            if not (0 <= attributes["position"] <= 100):
                return "窗帘位置需在 0-100 之间"
    return None
```

```python
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select, update
from sqlalchemy.dialects.mysql import JSON_SET
from app.models.device import Device, DeviceOperationLog
from app.database import get_db_session
import json

async def update_device_status(
    device_id: int,
    attributes: dict,
    user_id: int,
    source: str = "manual",
    family_id: int = None,
) -> Device:
    """更新设备状态，记录操作日志，返回更新后的设备。
    
    家庭隔离：若传入 family_id，校验设备属于该家庭，防止跨家庭操作。
    """
    async with get_db_session() as db:
        # 1. 查询设备当前状态（用于日志记录 before_status）
        device = await db.get(Device, device_id)
        if not device:
            raise ValueError(f"设备不存在: {device_id}")
        
        # 家庭隔离校验
        if family_id is not None and device.family_id != family_id:
            raise PermissionError(f"设备不属于家庭 {family_id}，无权操作")
        
        before_status = device.status
        
        # 2. 使用 MySQL JSON_SET 更新状态字段
        json_set_args = []
        for key, value in attributes.items():
            json_set_args.extend([f"$.{key}", value])
        
        stmt = (
            update(Device)
            .where(Device.id == device_id)
            .values(status=JSON_SET(Device.status, *json_set_args))
        )
        await db.execute(stmt)
        
        # 3. 记录操作日志（含 family_id）
        log = DeviceOperationLog(
            family_id=device.family_id,
            device_id=device_id,
            user_id=user_id,
            operation="update",
            source=source,
            before_status=before_status,
            after_status={**before_status, **attributes},
            description=f"更新属性: {list(attributes.keys())}",
        )
        db.add(log)
        
        await db.commit()
        await db.refresh(device)
        return device
```

```python
from fastapi import WebSocket
from typing import List, Dict, Any
import json
import asyncio

class WebSocketManager:
    """WebSocket 连接管理器，负责设备状态变更推送"""
    
    def __init__(self):
        self.active_connections: List[WebSocket] = []
    
    async def connect(self, websocket: WebSocket):
        await websocket.accept()
        self.active_connections.append(websocket)
    
    def disconnect(self, websocket: WebSocket):
        if websocket in self.active_connections:
            self.active_connections.remove(websocket)
    
    async def broadcast_device_update(self, message: Dict[str, Any]):
        """广播设备状态变更到所有连接的前端"""
        if not self.active_connections:
            return
        text = json.dumps(message, ensure_ascii=False)
        # 并发发送到所有连接
        await asyncio.gather(
            *[conn.send_text(text) for conn in self.active_connections],
            return_exceptions=True,  # 单个连接失败不影响其他
        )
    
    async def send_agent_response(self, websocket: WebSocket, message: Dict[str, Any]):
        """向特定连接发送 Agent 流式响应"""
        text = json.dumps(message, ensure_ascii=False)
        await websocket.send_text(text)

ws_manager = WebSocketManager()

async def broadcast_device_update(message: Dict[str, Any]):
    await ws_manager.broadcast_device_update(message)
```

```python
from typing import List
import re

class TextChunker:
    """文档切片器，将长文档切为适合向量化的片段"""
    
    @staticmethod
    def chunk_text(text: str, chunk_size: int = 500, overlap: int = 50) -> List[str]:
        """按字符数切片，带重叠"""
        chunks = []
        start = 0
        while start < len(text):
            end = start + chunk_size
            chunk = text[start:end]
            chunks.append(chunk)
            start = end - overlap
        return chunks
    
    @staticmethod
    def chunk_by_paragraph(text: str, max_size: int = 500) -> List[str]:
        """按段落切片，段落过长再按字符切"""
        paragraphs = re.split(r'\n\s*\n', text)
        chunks = []
        for para in paragraphs:
            if len(para) <= max_size:
                chunks.append(para)
            else:
                chunks.extend(TextChunker.chunk_text(para, max_size))
        return chunks
```

```python
import chromadb
from chromadb.config import Settings
from app.config import settings
from typing import List, Optional
import uuid

class VectorStore:
    """ChromaDB 向量库封装"""
    
    def __init__(self):
        self.client = chromadb.PersistentClient(path=settings.chroma_path)
        self.collection = self.client.get_or_create_collection("user_documents")
    
    async def add_documents(self, chunks: List[str], user_id: int, file_id: int,
                            embedder) -> List[str]:
        """向量化并存储文档片段"""
        embeddings = await embedder.embed(chunks)
        ids = [str(uuid.uuid4()) for _ in chunks]
        metadatas = [{"user_id": user_id, "file_id": file_id} for _ in chunks]
        
        self.collection.add(
            embeddings=embeddings,
            documents=chunks,
            ids=ids,
            metadatas=metadatas,
        )
        return ids
    
    async def query(self, query_text: str, user_id: int, top_k: int = 3,
                    embedder) -> List[dict]:
        """检索相关文档"""
        query_embedding = await embedder.embed([query_text])
        results = self.collection.query(
            query_embeddings=query_embedding,
            n_results=top_k,
            where={"user_id": user_id},
        )
        return [
            {"content": doc, "metadata": meta}
            for doc, meta in zip(results["documents"][0], results["metadatas"][0])
        ]
```

```python
async def execute_scene(scene_name: str, user_id: int) -> dict:
    """执行场景：批量更新多个设备状态"""
    async with get_db_session() as db:
        stmt = select(Scene).where(Scene.name == scene_name, Scene.is_active == 1)
        result = await db.execute(stmt)
        scene = result.scalar_one_or_none()
        if not scene:
            return {"success": False, "error": f"未找到场景: {scene_name}"}
        
        actions = scene.actions.get("actions", [])
        results = []
        for action in actions:
            room = await get_room_by_name(action["room_name"])
            if not room:
                results.append({"error": f"房间不存在: {action['room_name']}"})
                continue
            
            from app.services.device_service import get_device_by_room_and_type
            device = await get_device_by_room_and_type(room.id, action["device_type"])
            if not device:
                results.append({"error": f"设备不存在: {action['device_type']} in {action['room_name']}"})
                continue

                device_id=device.id,
                attributes=action["attributes"],
                user_id=user_id,
                source="agent",

            await broadcast_device_update({

                "device_id": device.id,
                "room_id": room.id,
                "device_type": action["device_type"],
                "status": updated.status,
            })
            results.append({"success": True, "device": device.name})
```

```python
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from app.models.family import Family
from app.models.user import User
from app.database import get_db_session

async def create_family_with_owner(
    family_name: str, owner_username: str, owner_nickname: str, description: str = None
) -> dict:
    """创建家庭 + 房主用户，一步完成绑定。
    
    流程：
    1. 创建房主用户（role=owner, family_id=0 临时）
    2. 创建家庭（owner_user_id 指向房主）
    3. 更新房主的 family_id 指向新家庭
    """
    async with get_db_session() as db:
        # 1. 创建房主用户
        owner = User(
            username=owner_username,
            nickname=owner_nickname,
            role="owner",
            family_id=0,  # 临时，创建家庭后更新
        )
        db.add(owner)
        await db.flush()  # 获取 owner.id
        
        # 2. 创建家庭
        family = Family(
            name=family_name,
            owner_user_id=owner.id,
            description=description,
        )
        db.add(family)
        await db.flush()  # 获取 family.id
        
        # 3. 更新房主的 family_id
        owner.family_id = family.id
        await db.commit()
        
        return {
            "family_id": family.id,
            "family_name": family.name,
            "owner_user_id": owner.id,
            "owner_username": owner.username,
        }

async def create_family_member(
    family_id: int,
    username: str,
    nickname: str,
    role: str,  # resident / guest
    creator_user_id: int,
) -> User:
    """房主在家庭下创建住户或访客。
    
    校验：
    - 创建者必须是房主（owner）
    - 创建者必须属于该家庭
    - 新用户自动绑定到同一家庭
    """
    async with get_db_session() as db:
        # 校验创建者权限
        creator = await db.get(User, creator_user_id)
        if not creator or creator.role != "owner":
            raise PermissionError("只有房主可以创建住户/访客")
        if creator.family_id != family_id:
            raise PermissionError("房主不属于该家庭")
        
        # 创建新用户，绑定到同一家庭
        new_user = User(
            username=username,
            nickname=nickname,
            role=role,
            family_id=family_id,
        )
        db.add(new_user)
        await db.commit()
        await db.refresh(new_user)
        return new_user

async def get_family_overview(family_id: int) -> dict:
    """获取家庭概览：含房间数、设备数、用户数"""
    async with get_db_session() as db:
        family = await db.get(Family, family_id)
        if not family:
            raise ValueError(f"家庭不存在: {family_id}")
        
        # 查询统计
        users_count = await db.scalar(
            select(func.count()).where(User.family_id == family_id)
        )
        rooms_count = await db.scalar(
            select(func.count()).where(Room.family_id == family_id, Room.is_active == 1)
        )
        devices_count = await db.scalar(
            select(func.count()).where(Device.family_id == family_id, Device.is_active == 1)
        )
        
        return {
            "family": family,
            "users_count": users_count,
            "rooms_count": rooms_count,
            "devices_count": devices_count,
        }
```

### 5.7 WebSocket 实时同步（composables/useWebSocket.js）★核心

```javascript
import { ref, onMounted, onUnmounted } from 'vue'
import { useDeviceStore } from '@/stores/device'
import { useAgentStore } from '@/stores/agent'
import { useUserStore } from '@/stores/user'  // 家庭隔离过滤

export function useWebSocket() {
  const ws = ref(null)
  const isConnected = ref(false)
  const reconnectAttempts = ref(0)
  const maxReconnect = 5
  let heartbeatTimer = null
  
  const deviceStore = useDeviceStore()
  const agentStore = useAgentStore()
  const userStore = useUserStore()  // 家庭隔离过滤
  
  const connect = () => {
    const wsUrl = `ws://${window.location.hostname}:8000/api/agent/ws`
    ws.value = new WebSocket(wsUrl)
    
    ws.value.onopen = () => {
      isConnected.value = true
      reconnectAttempts.value = 0
      startHeartbeat()
      console.log('WebSocket 已连接')
    }
    
    ws.value.onmessage = (event) => {
      const data = JSON.parse(event.data)
      handleMessage(data)
    }
    
    ws.value.onclose = () => {
      isConnected.value = false
      stopHeartbeat()
      if (reconnectAttempts.value < maxReconnect) {
        reconnectAttempts.value++
        setTimeout(connect, 3000)
      }
    }
    
    ws.value.onerror = (error) => {
      console.error('WebSocket 错误:', error)
    }
  }
  
  const handleMessage = (data) => {
    switch (data.type) {
      case 'device_status_update':
        // 家庭隔离：仅处理当前家庭的设备更新
        if (data.family_id === userStore.familyId) {
          deviceStore.updateDeviceFromWS(data)
        }
        break
      case 'agent_token':
        // Agent 流式输出 token
        agentStore.appendToken(data.content)
        break
      case 'agent_done':
        // Agent 回复完成
        agentStore.completeResponse(data.content)
        break
      case 'avatar_state':
        // 虚拟形象状态切换
        agentStore.setAvatarState(data.state)
        break
    }
  }
  
  const startHeartbeat = () => {
    heartbeatTimer = setInterval(() => {
      if (ws.value?.readyState === WebSocket.OPEN) {
        ws.value.send(JSON.stringify({ type: 'ping' }))
      }
    }, 30000)
  }
  
  const stopHeartbeat = () => {
    if (heartbeatTimer) clearInterval(heartbeatTimer)
  }
  
  const send = (data) => {
    if (ws.value?.readyState === WebSocket.OPEN) {
      ws.value.send(JSON.stringify(data))
    }
  }
  
  onMounted(connect)
  onUnmounted(() => {
    ws.value?.close()
    stopHeartbeat()
  })
  
  return { isConnected, send }
}
```

## 8. 扩展方向

### 8.1 短期优化（1-2 个月）

1. **真实知识图谱实现**：将 KG 节点从虚拟实现替换为真实图谱引擎（NetworkX + Neo4j），构建设备-房间-用户-场景关系图谱，支持自然语言转图查询。
2. **Agent 流式输出**：Agent 回复通过 WebSocket 流式推送 token，前端实现打字机效果，提升交互体验。
3. **设备模拟增强**：增加更多设备模拟器（灯泡色温渐变、窗帘光感自动调节），丰富演示效果。
4. **对话历史管理**：支持多会话切换、对话搜索、历史导出。
5. **偏好分析定时任务**：每日凌晨分析用户对话，更新偏好画像。

### 8.2 中期扩展（3-6 个月）

1. **真实设备接入**：通过 MQTT/ Zigbee 协议接入真实智能设备，从模拟走向落地。
2. **多模态交互**：支持图像输入（如拍摄设备照片识别型号）、视频输入（手势识别控制）。
3. **联邦学习**：多用户偏好画像的联邦学习，在保护隐私前提下提升推荐准确度。
4. **边缘部署**：将 LLM 与 Whisper 模型部署到边缘设备，降低延迟与成本。
5. **数字孪生**：构建家庭 3D 数字孪生模型，设备状态可视化更直观。
6. **语音克隆**：基于用户少量语音样本克隆专属 TTS 音色。
7. **跨家庭协同**：支持多家庭、多房屋管理，Agent 跨房屋推理。

### 8.3 长期愿景

1. **多 Agent 协同**：引入设备管理 Agent、安全监控 Agent、能耗优化 Agent 等专业 Agent，协同工作。
2. **主动智能**：Agent 基于用户习惯主动推荐操作（如"您通常 23 点睡觉，要关闭客厅灯吗？"）。
3. **情感计算**：通过语音语调、文字情感分析用户情绪，调整回复风格。
4. **能耗优化**：基于设备使用模式分析能耗，提供节能建议。
5. **安全审计**：完整的设备操作审计链，支持回溯与异常检测。

## 9. 开发规范与约定

### 9.1 代码规范

- **后端**：遵循 PEP 8，使用 `black` 格式化、`ruff` 检查；类型注解必填；docstring 使用 Google 风格。
- **前端**：遵循 ESLint + Prettier 配置；组件名使用 PascalCase；Composables 使用 `use` 前缀。
- **命名约定**：
  - 后端文件名：snake_case（如 `device_service.py`）。
  - 前端文件名：PascalCase（如 `DeviceView.vue`）。
  - 数据库表名：snake_case 复数（如 `devices`）。
  - 数据库字段：snake_case（如 `created_at`）。
  - API 路径：snake_case（如 `/api/devices/{id}/status`）。

### 9.2 Git 规范

- 分支策略：`main`（生产）、`develop`（开发）、`feature/*`（功能）、`fix/*`（修复）。
- Commit 规范：`<type>(<scope>): <subject>`，type 包括 feat/fix/docs/style/refactor/test/chore。
- PR 规范：必须包含描述、测试方案、影响范围。

### 9.3 测试规范

- 后端：pytest 单元测试覆盖率 ≥ 70%，关键服务（device_service、agent 工具、LLM 适配层）≥ 90%。
- 前端：Vitest 组件单元测试 + Playwright E2E 测试。
- 接口测试：使用 pytest + httpx 编写接口测试用例，覆盖正常与异常路径。
- **核心链路验证**：必须编写"将卧室空调调整到 27 度"的端到端测试，确保数据库状态、WebSocket 推送、前端更新全链路正确。

### 9.4 错误处理规范

- 后端统一异常处理器，返回标准错误响应格式 `{ code, message, detail }`。
- 前端 axios 拦截器统一处理网络错误，展示 Element Plus 消息提示。
- 所有外部调用（LLM、Whisper、TTS、ChromaDB）必须有超时与重试机制。
- LLM 调用失败时，Agent 应回退到规则匹配模式，确保基本功能可用。

### 9.5 日志规范

- 使用 `loguru` 统一日志格式：`{time} {level} {module}:{function}:{line} {message}`。
- 日志级别：DEBUG（开发）、INFO（业务关键节点）、WARNING（可恢复异常）、ERROR（不可恢复异常）。
- 敏感信息（API Key）脱敏后记录。
- 日志输出到文件 + 控制台，文件按日切割，保留 30 天。
- Agent 每次工具调用记录详细日志（工具名、参数、结果、耗时），便于调试。

### 9.6 文档规范

- API 文档：FastAPI 自动生成 OpenAPI，访问 `/docs` 查看。
- 数据库文档：每次表结构变更需同步更新本文档第 3 章。
- 接口变更：需在 PR 描述中说明变更影响。
- LLM 适配层变更：新增模型适配器时，需更新第 4.4 节并补充测试用例。

### 9.7 LLM 适配层使用规范 ★

- **业务代码禁止直接调用模型 SDK**，必须通过 `get_llm_client()` 获取统一客户端。
- **新增模型适配器**时，继承 `BaseLLMClient`，实现 4 个抽象方法，在 `factory.py` 注册。
- **工具定义**统一使用 `ToolDefinition` 类，参数格式遵循 JSON Schema。
- **消息格式**统一使用 `Message` 类，禁止直接构造 dict。
- **切换模型**时，修改 `.env` 中 `LLM_PROVIDER`，调用 `reset_llm_client()` 重置单例。
- **测试**：每个适配器需编写独立测试，验证 chat、chat_with_tools、stream_chat、embed 四个方法。
