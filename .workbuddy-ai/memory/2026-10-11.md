## 后端 / Agent 架构评审

应"分析当前项目后端逻辑尤其是 agent 架构，有哪些需要改进的"要求，通读 `backend/app` 全部 91 个 Python 模块，产出评审文档 `后端与Agent架构评审.md`（项目根目录）。

核心结论（P0 级，均为"单链路正常、多链路崩溃"类盲区）：

1. **P0-1** `avatar_emotion` 无 reducer，被 chat/rag_answer/report/approval 四节点并发写入 → LangGraph `InvalidUpdateError`。多意图请求（chat+knowledge 等）直接 500。
2. **P0-2** `api/agent.py::_run_langgraph_stream` 用 `final_state.update()` 手工聚合 `stream_mode="updates"` 增量，绕过 `chain_results` 的 `or_` reducer → WebSocket 入口丢链路结果，与 HTTP `ainvoke` 入口行为不一致。
3. **P0-3** `/agent/resume` 未校验 thread 归属（`thread_id` 由客户端 session_id 派生），可越权恢复他人中断态并以对方身份继续执行。
4. **P0-4** `graph.py::route_after_clarify` 在路由函数里直接改 `state`（`active_chains`/`needs_clarification`），路由函数副作用不写回 channel → 取消澄清后链路标记错乱。
5. **P0-5** `rules/intent.py` 中 `water_heater` 分支重复（178 行 / 239 行），第二个不可达 → 热水器温度设置永久失效。
6. **P0-6** `websocket/manager.py::broadcast_device_update` 全量广播，靠前端按 family_id 过滤 → 跨家庭设备状态泄露。

P1 重点：MemorySaver 多进程/重启失效、工具结果不回灌 LLM（实为计划-执行流水线）、假流式+假进度（`stream_chat` 定义了从未调用）、LLM 无超时重试、会话历史双来源（reset 不清 checkpoint）、同请求重复查库 3 次、`permission_mode` 客户端可自传 high 绕过审批、`MAX_ITERATIONS`/`iteration` 死代码。

已认可的架构优点：意图优先不预查库、多链路 fan-out、双路降级 + `model_warning`、家庭隔离贯穿工具层（`_require_control_permission`、只读设备硬拦）。

## 上线就绪度评估

应"从项目可上线角度分析还需要哪些改进"要求，产出 `上线就绪度评估.md`（项目根目录）。八个维度：安全/可靠性/性能/合规/可观测性/部署/成本/业务完整性。

**结论**：功能完成度高，生产化程度低。已确认的良好基础：51 个 REST 路由全部挂鉴权依赖、init.sql 有完整外键与复合索引、.gitignore 规范（实测 backend/.env 未被 git 跟踪，plugins/node_modules 未入库，175 个跟踪文件）、parse_file 用了 to_thread。

**安全红线（S1–S8）**：密码明文存储（auth_service.py，docstring 自述"演示模式"）；登录/注册无限流（可暴力破解 + 批量刷号消耗 LLM 额度）；JWT 无吊销且 role/family_id 写死在 token 里（踢人后 24h 内旧 token 仍可控制设备）；jwt_secret 有硬编码默认值（config.py:67）；上传大小校验在 `await file.read()` 全量读内存**之后**（api/file.py:50-54，OOM 型 DoS）；CORS 写死 localhost（main.py:59-69）；JWT 存 localStorage；WS token 走 URL query。

**可靠性**：`rebuild_file_vectors()` 在每次启动时 `clear_all()` + 全量重算 embedding（知识问答期间不可用、启动时间线性增长、中途失败残缺、重复烧钱）——最痛一条；文件处理 `asyncio.create_task` fire-and-forget 且未保存 Task 引用（api/file.py:70，可被 GC、无队列无重试、重启卡 processing）；无 Alembic 靠启动时 ALTER TABLE；无优雅停机；四处状态零备份。

**性能**：LLM client 全都没传 timeout → 走 OpenAI SDK 默认 600s + 2 次重试；前端 axios 超时 30s 可能短于 /agent/chat 真实耗时（导致"前端以为失败、后端已执行设备控制"）；无并发/配额；ws_manager 单机内存态；Dockerfile 单 worker。

**合规（国内硬门槛）**：生成式 AI 备案、AI 生成内容标识、内容安全审核、隐私政策与用户协议、账号注销、实名——全部未涉及。

**可观测性**：无 logging 配置；log_node_run 把整个节点返回值打进日志（含用户对话+设备数据）；无 trace_id；无 metrics（LLMResponse.usage 拿到即丢）；健康检查只有静态 GET /；无错误上报。

**部署**：无 CI/CD；vite 无生产构建配置；WS 默认 `ws://`+硬编码 8000（HTTPS 下混合内容被拦，useWebSocket.js:83）；容器 root 运行单阶段；无 .dockerignore。

**缺失业务能力**：忘记密码/重置、账号注销、多端登录管理、操作审计查询（device_operation_logs 有数据无 API）、批量导入。

## 修复安全红线（S1–S5 + CORS）

用户要求"先修复最严重的问题"，即上线阻断清单前 5 项。业务逻辑未做语义变更。

- **S1 密码哈希**：新增 `services/password_service.py`（bcrypt + sha256 预哈希，规避 bcrypt 72 字节上限；不用 passlib —— 已停维护且依赖 Python 3.13 移除的 crypt 模块）。`auth_service` 接入；**历史明文密码在首次成功登录时自动升级为哈希**（`verify_and_maybe_upgrade` 返回 `(ok, needs_upgrade)`），无需迁移脚本。`family_service.py:71` 的 `hash_password` 调用自动受益。
- **S2 限流**：新增 `services/rate_limit.py`（`SlidingWindowCounter` + 模块级函数；key 截断 128 字符、上限 20000 key 防内存滥用）。`/auth/login` IP 限流 20 次/5min + 账号失败 5 次锁 15min（**用户名不存在也计失败，防枚举**）；`/auth/register` IP 限流 5 次/小时。进程内实现，多副本下阈值会被放大，需换 Redis。
- **S3 token 不可撤销**：重写 `api/deps.py` —— token 只作身份凭据，`role`/`family_id` 每次回查 DB（`_load_identity` + 10 秒 TTL 缓存）。`current_user_payload_from_query` 改 async 并回查；`api/agent.py:612` 调用点加 `await`。降级/踢人由 24 小时窗口变为立即生效。
- **S4 密钥强制**：`config.py` 加 `app_env` / `is_production` / `cors_origins` / `cors_origin_list`；`main.py` 加 `_validate_security_settings()`（lifespan 最前调用），production 下 jwt_secret 仍为默认值即 `RuntimeError` 拒绝启动，development 下 warning。
- **S5 上传大小**：`api/file.py` 加 `_read_upload_within_limit`（Content-Length 预检 + 1MB 分块流式读取，超限返回 413），替换 `await file.read()` 全量读内存；`/agent/stt` 同类问题一并修（`config.py` 新增 `max_audio_size`）。
- **S6 CORS**：`main.py` 从 `settings.cors_origin_list` 读取。
- **配套**：`requirements.txt` 加 `bcrypt>=4.1`；`.env.example` 加 `APP_ENV`/`CORS_ORIGINS`；`init.sql` 加密码升级说明；前端 `api/request.js` 让 `/auth/login`、`/auth/register` 的 401 不触发登出跳转（否则账号锁定提示会被"登录已过期"覆盖）。

**遗留待用户决策**：`family_service.create_family_with_owner` 硬编码默认密码 `123456`（代码与 docstring 一致），且不返回给调用者 → 知道该值即可登录新建家庭的房主账号。修复需前端加"设置新家庭密码"输入项，属 API 契约变更，未擅自改。
